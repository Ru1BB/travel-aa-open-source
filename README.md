# 同行 · Travel AA

**把旅程账单整理清楚，算出谁该给谁多少钱。**

同行是一款可自行部署的多人出游 AA 账本。管理员创建旅程并分配成员，大家通过浏览器上传自己的微信或支付宝账单，确认哪些消费需要共同承担，最后获得转账清单和 Excel 报表。

适合朋友旅行、小团体活动及多人垫付后的费用结算。电脑、安卓和 iPhone 共用同一个网页。

## 功能

- **独立旅程**：每次出游单独维护日期、成员、账单与结算记录。
- **账号与权限**：管理员管理账号、创建旅程；成员仅能进入被分配的旅程。
- **账单导入**：支持微信、支付宝个人账单的 CSV / XLSX 格式，按开始和结束日期筛选，识别重复导入。
- **手动记账**：补录消费，指定实际垫付者及分摊成员。
- **逐笔及批量确认**：导入后进入待确认状态，可编辑、删除、多选修改消费类型和分摊成员，再确认纳入结算。
- **灵活分摊**：共同消费默认全员均分，可以取消不参与的人；私人消费不计入 AA。
- **转账建议**：按每人的垫付与应承担金额计算净额，生成“谁向谁转多少钱”的清单。
- **Excel 导出**：导出个人汇总、共同消费明细和转账清单，并保存当次结算快照。
- **管理后台**：管理用户、上传及导出文件，查看各次旅程的结算记录。

## 怎么使用

1. 管理员创建成员账号和旅程，填写出游日期并选择成员。
2. 成员登录，进入指定旅程，导入本人账单或手动录入。
3. 在消费明细中确认共同 / 私人类型，调整实际分摊人员。
4. 点击账单的“上传”按钮提交确认；也可以多选后批量上传。
5. 查看结算结果，导出 Excel，按转账建议自行完成支付。

界面中的“上传”表示**提交确认并更新结算**。原始账单文件在导入时已经保存；编辑暂存在当前页面，提交前不会改变结算。关闭页面前请提交需要保留的编辑。

只有已确认的共同消费参与 AA。金额按整数分计算，尾差按旅程成员顺序分配；垫付者可以不参与分摊。系统提供转账建议，不发起真实支付，也不保证转账笔数在数学上最少。

普通成员不能修改其他人的账单，也看不到其他人的私人账单及原文件。管理员具有管理与查阅权限，但不能替上传者修改账单。

## 技术栈

| 层次 | 实现 |
| --- | --- |
| 网页 | 原生 HTML、CSS、JavaScript，响应式布局 |
| 后端 | Python 标准库 HTTP 服务 |
| 数据库 | SQLite |
| CSV / Excel | Python 标准库 CSV、ZIP、XML 解析与 OOXML 输出 |
| 部署 | Linux、Nginx、systemd、HTTPS |
| 验证 | Python unittest、Node.js 内置测试框架 |

应用运行不需要安装第三方 Python 或 npm 包。Node.js 用于可选启动包装、前端构建与 JavaScript 结算测试。生产共享账本的结算以 Python 后端为准。

## 本地运行

需要 Python 3.11 或更新版本；运行 JavaScript 测试另需 Node.js。

```bash
git clone https://github.com/Ru1BB/travel-aa-open-source.git
cd travel-aa-open-source
python web_server.py
```

打开 [http://localhost:5173](http://localhost:5173)。空数据库且未配置初始管理员环境变量时，从本机页面完成首次管理员设置。密码支持 6–128 个字符；公开部署建议使用更长的独立密码。

默认数据库与上传文件写入本地 `data/`，该目录不应提交 Git。停止服务使用 Ctrl+C。

```bash
python -m unittest test_backend
node --test
node --check app.js
```

测试使用合成账单和隔离临时数据库。仓库中的 `samples/` 仅包含虚构示例。

## 部署与数据

这是带后端和数据库的应用，不能仅用 GitHub Pages 或上传 `dist/` 来运行。公开服务需要持续运行 Python 后端，并通过 HTTPS 反向代理访问。

首次安装可通过 `TRAVEL_AA_ADMIN_USERNAME`、`TRAVEL_AA_ADMIN_PASSWORD` 环境变量初始化管理员，只在数据库完全没有账号时生效。凭据应保存在服务器私有配置中，不能写入代码、文档或 Git。

代码和业务数据应分开存放。正常更新应保留已有账号、账本、原始文件与历史快照；清库不能作为常规发布步骤。删除物理文件不会删除已经解析的账目或结算快照。

部署脚本通过参数接收服务器地址、公开域名、证书名与内部端口；模板必须先渲染，不能直接安装。目录和服务名沿用 travel-aa 的约定，详见 [部署说明](deploy/README.md)。项目不会自动推送 GitHub、自动发布或自动备份业务数据。备份说明见 [BACKUP.md](BACKUP.md)。

## 支持范围

- 面向小规模、单服务器使用，暂无实时通知与公开自助注册。
- 支持的账单表头、状态与限制见 [IMPORT.md](IMPORT.md)，不承诺兼容所有平台导出版本。
- 退款、转账、红包等可能不代表共同消费；部分退款需人工核实净额。
- 未提交的页面编辑不会跨设备同步，刷新或关闭页面可能丢失。
- 结算快照保留生成时的结果，后续改账不会改写历史快照。
- 不开发原生安卓或 iOS 应用。
